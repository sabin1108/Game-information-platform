# 검색·필터 UX와 React 성능 개선 사례

## 해결한 사용자 문제

게임 제목 검색 응답에는 장르가 없는데 상품 유형 `game`을 태그로 처리했고, 제목 없이 태그만 선택하면 예시 데이터만 검색했습니다. 헤더와 본문에는 서로 독립된 검색창이 있었으며 같은 제목에서 스토어만 바꿔도 외부 제목 검색을 반복했습니다. 검색창 자체가 가격 조회를 기다리는 것도 입력 시작을 지연시켰습니다.

## 구현과 설계 근거

- **URL을 적용된 상태의 기준으로 사용**: 제목·태그·스토어·최대 원화 가격·할인 여부·정렬을 하나의 정규화 함수로 처리합니다. 서버, API, 폼, 조건 해제 링크, 인증 복귀가 같은 계약을 사용합니다.
- **입력과 결과 렌더링 분리**: SearchControls는 서버 컴포넌트의 uncontrolled GET 폼입니다. 입력을 결과 목록 상위 React state로 올리지 않습니다. 결과를 별도의 서버 Suspense 경계로 분리해 검색 조건을 먼저 전송합니다.
- **두 검색 의도를 구분**: 제목이 있으면 공식 제목 API의 최대 100개 결과 안에서 조건을 적용합니다. 제목이 없으면 공식 할인 API에 태그 조건을 전달합니다. 전체 게임 카탈로그를 빠짐없이 검색한다고 주장하지 않습니다.
- **정확한 메타데이터**: 게임 UUID로 실제 태그와 표지를 가져옵니다. 제목 유사도에 의존해 다른 게임의 태그를 붙이지 않습니다. 기존 표지 조회와 동일 ID 캐시를 공유합니다.
- **불필요한 외부 요청 감소**: 제목 결과 캐시에서 로컬 조건을 분리하고, 진행 중인 동일 후보 조회를 공유합니다. 가격 필터는 선택한 스토어의 동일 판매 정보에 적용합니다.
- **한국어 필터와 복구**: 로그라이크/Rogue-like/Roguelite 등의 의미를 정규화하고, 자유 입력 대신 선택 가능한 태그를 제공합니다. 조건별 제거와 제목을 보존하는 필터 초기화, 로딩 및 실패 안내를 제공합니다.
- **전송량 관리**: 새 필터 UI를 서버에서 렌더링해 별도 클라이언트 상태관리 라이브러리나 차트 패키지를 추가하지 않았습니다. 프로덕션 빌드의 검색 경로는 기존과 동일하게 route size 488B, First Load JS 108kB였습니다. 이는 번들 감소 주장이 아니라 기능 추가에도 해당 빌드 지표가 증가하지 않았다는 관찰입니다.

검색 조건이 결과보다 먼저 도착하는 구조를 확인했습니다. **실사용 LCP/INP 또는 평균 검색 속도 개선율을 측정한 결과가 아닙니다.** 실제 태그 보강으로 초기 결과 조회가 느려진 샘플도 있습니다. 전체 검색이 빨라졌다고 쓰면 안 됩니다.

- React Profiler 컴포넌트 테스트: 검색 입력 20회 변경 동안 mount 이후 update commit 0회. 새 입력 구조의 동작 검증이며, 기존 전체 페이지 대비 리렌더 감소율은 측정하지 않았습니다.
- 브라우저 테스트: 제목 입력 중 추가 검색 요청 0회, 기존 결과 개수 유지.
- 모의 공급자 테스트: 같은 제목에 대한 동시 조건 요청 4개가 외부 제목 조회 1회와 메타데이터 보강 1회를 공유합니다. 추가 필터 변경에서도 제목 후보를 재사용합니다.
- 게임 정보 보강은 배치당 최대 4개 동시 조회·4초 예산, ID당 24시간 캐시·실패 시 짧은 재시도 캐시를 사용합니다. 누락 태그는 추정하지 않고 필터 적용 시 안내합니다.
- 실제 Hades + 로그라이크는 Hades/Hades II 두 게임으로 좁혀졌습니다. 검증 중 태그 단독 탐색은 공급자 429 응답을 받아 예시 상태로 전환된 사례가 있었습니다. 이후 00:26 KST 재확인에서는 HTTP 200, source=itad, 실제 할인 게임 40개를 반환했습니다. 공급자 가용성과 전체 태그 수집 완전성을 보장하지 않습니다.
- GET 폼을 사용하지만 Next.js 스트리밍 화면 전체의 JavaScript 비활성 지원은 검증 범위가 아닙니다.

## 참고 문서 적용 판단

사용자 문서: `D:/sabin/note/coding/공부/공부용/WEB_study/리액트 성능 향상을 위한 방법.md`.

상태를 필요한 위치에 유지, 고유한 게임 ID key, 이미지 지연 로딩, 무거운 의존성 회피, API 캐시, 오류 복구, 프로파일링을 적용했습니다. 입력마다 검색하지 않는 명시적 제출이므로 디바운스는 추가하지 않았습니다. 서버 렌더링 폼에 불필요한 memo/useCallback을 넣거나, 비용 근거 없이 lazy·Context를 추가하지 않았습니다. 인라인 함수 자체를 결함으로 취급하거나 React 최신 버전으로 무조건 업그레이드하지 않았습니다.

React는 메모화를 성능 최적화로 설명하며 로컬 상태 유지와 실제 프로파일링을 권장합니다. [React memo](https://react.dev/reference/react/memo), [React Profiler](https://react.dev/reference/react/Profiler). 제목 검색과 태그 메타데이터 및 tagsUnion 계약은 [ITAD 공식 API 문서](https://docs.isthereanydeal.com/)에 근거합니다.

## 이력서 문장 예시

> 게임 가격 비교 서비스의 검색을 URL 기반 필터 상태와 서버 스트리밍 구조로 재설계해, 가격·태그 조회가 완료되기 전 검색 조건을 먼저 제공하고 필터·인증 전환 시 사용자 검색 맥락을 보존했습니다.

> 서버 컴포넌트와 uncontrolled 폼으로 입력과 결과 목록의 업데이트 경계를 분리하고, Profiler 테스트에서 입력 20회 동안 폼의 업데이트 커밋 0회를 검증했습니다. 동일 제목의 필터 변경은 후보 캐시와 진행 중 요청을 공유하도록 구현했습니다.

숫자를 포함할 경우 위 조건과 재현 방법을 함께 설명하세요. 개인 기여와 프로젝트 전체 기여도는 실제 작업 이력에 맞게 조정해야 합니다.
